# ДЗ: 11. Брокеры сообщений (JMS, AMQP, Kafka)

Использовал Kafka

Создал два проекта:

- consumer
- producer

Назначение совпадает с названием

Значения параметров `KafkaListener`:

- `id` - id слушателя, потом по нему можно управлять через `KafkaListenerEndpointRegistry`
- `containerFactory` - имя бина типа `KafkaListenerContainerFactory`. Можно не указывать, тогда использует бин с именем
  `kafkaListenerContainerFactory`
- `topics` - какие топики слушаем
- `topicPattern` - слушаем топики, если соответствуют регулярке
- `topicPartitions` - способ самому вручную назначать партиции. Используется аннотация `TopicPartition`. `topic` -
  название топика, `partitions` - список партиций, `partitionOffsets` - аннотация `PartitionOffset`(настройка
  начального сдвига и т.п.)
- `containerGroup` - смысл схож с параметром `id`, только здесь мы объединяем в целые группы
- `errorHandler` - обработчик ошибок, по умолчанию бин с именем `kafkaListenerErrorHandler`
- `groupId` - id группы потребителей в кафке
- `idIsGroup` - Использовать groupId как id группы потребителей в кафке?
- `clientIdPrefix` - добавляет префикс к id
- `beanRef` - определяет, к какому бину принадлежит этот слушатель
- `concurrency` - сколько создать слушателей. Перезаписывает значение из фабрики
- `autoStartup` - запускать ли слушатель при старте приложения?
- `properties` - можно задать свойства (переопределить) прямо в аннотации
- `splitIterables` - если мы читаем сообщения батчами, то разделить ли их так, как будто мы читаем их по одному?
- `contentTypeConverter` - конвертация на основе MIME типа (но он должен в заголовке тогда передаваться)
- `batch` - принимает true/false. Если true, то получаем на обработку списки сообщений
- `filter` - обработка сообщений, соответствующих фильтру
- `info` - по сути просто строка с какой-то инфой. Добавляется в заголовок
- `containerPostProcessor` - контейнер слушателей создался --> доп действия
